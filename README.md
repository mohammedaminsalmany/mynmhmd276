# Doca

> A modern, lightweight **docs-as-code** engine and static documentation generator — pure Python, zero dependencies.

[![CI](https://github.com/mohammedaminsalmany/doca/actions/workflows/ci.yml/badge.svg)](https://github.com/mohammedaminsalmany/doca/actions/workflows/ci.yml)
[![Python](https://img.shields.io/badge/python-3.10%2B-blue.svg)](https://www.python.org/downloads/)
[![Dependencies](https://img.shields.io/badge/dependencies-0-brightgreen.svg)](#architecture)
[![License: MIT](https://img.shields.io/badge/license-MIT-yellow.svg)](LICENSE)

Doca turns a folder of Markdown files into a fast, clean documentation site
with a collapsible sidebar, full-text search, automatic tables of contents and
a dark/light theme. Everything — the Markdown parser, the HTML templates, the
CSS and the search — lives in the repository, so a build needs nothing but
Python itself.

```bash
pip install -e .
doca init my-docs
cd my-docs
doca serve
```

---

## Features

- **Zero required dependencies** — the base engine runs on the Python standard library alone.
- **Fast builds** — a typical site renders in milliseconds, with no bundler or Node toolchain.
- **Markdown engine included** — headings, nested lists, tables, fenced code blocks, block quotes, front matter, inline formatting, task lists and escaped HTML.
- **Auto-generated table of contents** — a nested "On this page" outline on every page, with scroll-spy highlighting.
- **Client-side search** — instant results across all pages, keyboard-first (`Ctrl K` or `/`).
- **Responsive by default** — collapsible sidebar, mobile menu and a layout that works from phone to widescreen.
- **Light, dark or auto theme** — follows the reader's system preference and remembers their choice.
- **Explicit or automatic navigation** — group pages in `doca.json`, or let Doca list them for you.
- **Static output** — plain HTML, CSS and a few lines of vanilla JavaScript; host it anywhere.

## Quickstart

### 1. Install

Doca requires **Python 3.10 or newer**.

```bash
git clone https://github.com/mohammedaminsalmany/doca.git
cd doca
pip install -e .
```

Or run it straight from the checkout, without installing:

```bash
python -m doca --version
```

### 2. Create a workspace

```bash
doca init my-docs
cd my-docs
```

```text
my-docs/
├── doca.json
├── .gitignore
├── docs/
│   ├── index.md
│   ├── getting-started.md
│   └── configuration.md
└── site/            # generated by `doca build`
```

### 3. Build and preview

```bash
doca build           # render into site/
doca serve           # http://127.0.0.1:8000, rebuilds on change
```

### 4. Write a page

```bash
doca new guides/deployment --title "Deployment"
```

```markdown
---
title: Deployment
description: Ship a Doca site to production.
order: 3
---

# Deployment

The output is static — upload `site/` anywhere.
```

## Architecture

Doca is deliberately small. Four modules make up the whole engine:

```text
doca/
├── doca/
│   ├── __init__.py      # package metadata and public API (v0.1.0)
│   ├── __main__.py      # enables `python -m doca`
│   ├── cli.py           # argparse CLI: init, build, serve, new
│   ├── builder.py       # Markdown → HTML, TOC, navigation, site assembly
│   ├── templates.py     # embedded HTML/CSS/JS page template
│   └── py.typed         # PEP 561 marker
├── docs/                # starter documentation (this site)
│   ├── index.md
│   ├── getting-started.md
│   └── configuration.md
├── tests/               # unittest suite (builder + CLI)
├── doca.json            # site configuration
├── pyproject.toml       # packaging and console entry point
├── setup.py             # compatibility shim
├── .github/workflows/   # CI on Python 3.10, 3.11 and 3.12
├── LICENSE              # MIT
└── README.md
```

### Build pipeline

```text
 docs/*.md ──► front matter ──► block parser ──► inline renderer ──► HTML
                                     │
                                     ├──► heading ids + table of contents
                                     ├──► navigation (explicit or generated)
                                     └──► search index ──► embedded JSON
                                              │
                                              ▼
                                     templates.render_page()
                                              │
                                              ▼
                                       site/*.html + search-index.json
```

The Markdown engine lives in `builder.py::render_markdown`. It parses front
matter, walks the document block by block (fenced code, headings, quotes,
tables, lists, paragraphs), renders inline formatting, assigns stable heading
slugs and returns HTML plus the heading tree used for the table of contents.
`build_site` then renders every page, resolves navigation and writes the
static output.

## CLI reference

| Command | Description |
| --- | --- |
| `doca init [path]` | Scaffold a workspace with `doca.json`, `docs/` and sample pages. |
| `doca build` | Render Markdown into static HTML in `out_dir` (`site/` by default). |
| `doca serve` | Build and serve the site locally, rebuilding when files change. |
| `doca new <page-name>` | Create a Markdown page with front matter in `docs/`. |

Global options:

| Flag | Description |
| --- | --- |
| `-V`, `--version` | Print the Doca version and exit. |
| `-C`, `--dir <path>` | Run against a project directory other than the current one. |

Command options:

```bash
doca build --out public        # custom output directory
doca build --quiet             # no console output
doca serve --port 8080         # choose a port
doca serve --host 0.0.0.0      # listen on all interfaces
doca serve --open              # open the browser
doca serve --no-watch          # disable auto-rebuild
doca new guides/deploy --title "Deployment" --force
```

## Markdown support

| Syntax | Rendered as |
| --- | --- |
| `# Heading` … `###### Heading` | `<h1>`–`<h6>` with anchor links and stable ids |
| `**bold**`, `*italic*`, `~~strike~~` | strong, emphasis, strikethrough |
| `` `code` `` and fenced blocks | inline code and labelled code blocks with copy buttons |
| `- item`, `1. item`, indented lists | nested `<ul>` / `<ol>` |
| `- [x] done` | task lists with checkboxes |
| `\| tables \|` | tables with left/center/right alignment |
| `> quote` | block quotes |
| `[text](page.md)` | links, with `.md` rewritten to `.html` automatically |
| `![alt](image.png)` | responsive images |
| `---` | horizontal rules |
| `---` front matter | per-page title, description and order |

Raw HTML is escaped rather than passed through, which keeps generated sites
predictable and safe by default.

## Configuration

`doca.json` at the project root controls the site. Every key is optional:

```json
{
  "title": "Doca Docs",
  "description": "Documentation built with Doca.",
  "author": "Mohammed Amin Salmany",
  "docs_dir": "docs",
  "out_dir": "site",
  "theme": { "accent": "#6366f1", "default": "auto" },
  "nav": [
    { "title": "Introduction", "path": "index.md" },
    {
      "title": "Guides",
      "items": [
        { "title": "Getting started", "path": "getting-started.md" },
        { "title": "Configuration", "path": "configuration.md" }
      ]
    }
  ]
}
```

See [`docs/configuration.md`](docs/configuration.md) for the full reference,
including footer links, edit links and how to hide draft files.

## Development

```bash
git clone https://github.com/mohammedaminsalmany/doca.git
cd doca
python -m unittest discover -s tests -v
doca build
```

The test suite covers front matter, heading slugs and TOC nesting, inline and
block rendering, tables, lists, code blocks, navigation, search indexing, the
CLI parser and end-to-end builds. CI runs the same commands on Python 3.10,
3.11 and 3.12.

### Project conventions

- Python 3.10+ with `from __future__ import annotations`.
- Standard library only — no runtime dependencies.
- Public functions carry docstrings, and modules stay focused: parsing and
  building in `builder.py`, presentation in `templates.py`, orchestration in
  `cli.py`.
